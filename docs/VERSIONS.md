### الرجوع إلى V4
```bash
git revert --no-edit <التزام V4.1>        # يعيد session.js وrun.mjs والواجهة وsw.js (V يُرفع لا يُنزَل)
# ثم موعد Confirm إلى :03 — schedule.ps1 يعود معه، والمجدول:
powershell -c "$t=(Get-ScheduledTask WebTrade-Confirm).Triggers[0]; $t.StartBoundary=$t.StartBoundary -replace 'T(\d\d):\d\d','T$1:03'; Set-ScheduledTask WebTrade-Confirm -Trigger $t"
```
الحالة (`trades-state.json`) متوافقةٌ في الاتجاهين: الصفقات تُمشى من آخر لقطة أيّاً كانت الخطوة.

## التبديل — أداةٌ واحدة في الاتجاهين

```bash
node scripts/switch-engine-version.mjs --to v3                      # خطةٌ فقط (افتراضي)
node scripts/switch-engine-version.mjs --to v3 --apply --no-merge   # تجهيزٌ وفحص في worktree، main لا يُمسّ
node scripts/switch-engine-version.mjs --to v3 --apply              # التبديل الفعلي محلياً
git push origin main                                                 # ثم النشر كالعادة
node scripts/check-live.mjs                                          # التحقّق على الرابط المنشور
```
و`--to v4` للعودة إلى V4 بنفس الخطوات.

### ما يفعله `--apply` بالترتيب
1. **الكود في worktree مؤقّت لا في الشجرة الرئيسية**: كلُّ ملفٍّ يختلف بين `v3-stable` و`v4.0.0` (22 ملفّاً)
   يُستعاد من الوسم الهدف، والمضاف في V4 يُحذف عند الرجوع إلى V3. أداة التبديل وهذا الملفّ يبقيان.
   السبب: المجدول يشغّل الشجرة الرئيسية كلَّ دقائق، وتعديلُها ملفّاً ملفّاً نشر نصفَ نسخة (2026-10-03).
2. **عامل الخدمة**: `V` يُرفع فوق الحالي دائماً (الرجوع إلى V3 يعطي `webtrade-v57` لا `v55`) و`SHELL_SHA`
   يُطابَق — فيثبّت كلُّ متصفّحٍ الهيكلَ الجديد كاملاً ويحذف ذاكرة النسخة الأخرى، بلا خليطٍ من نسختين.
3. **الفحوص قبل أيّ التزام**: `check-ui` · `build-trades --check` · `node --check` · اختبارات engine3 للنسخة
   الهدف. أيُّ فشلٍ يوقف ولا يمسّ main.
4. **تقديم main خطوةً واحدة** (`git merge --ff-only`) — تبديلٌ ذرّي تقريباً لما يشغّله المجدول.
5. **البيانات**: `trades-state.json` للدفترين **يُنقل لا يُحذف** إلى `data/.archive/state-before-<to>-<وقت>/`،
   ثم `trades.json` يُبنى بكود الهدف من مخزن الشموع نفسه (الكود حتميّ: V3 يعيد لقطته من الشموع المغلقة
   كما كان يفعل). وحارس الرتابة في النشر يسمح بتغيّر نسخة المحرّك داخل الشمعة نفسها.
6. لا يدفع: `git push` يدوي، ثم `site.yml` ينشر الواجهة بعد بوّابته، و`WebTrade-Publish` ينشر البيانات.

### التوافق والذاكرة المؤقّتة
- **واجهة V3 مع بيانات V4** (أثناء دقائق الانتقال): تعمل — الحقول التي تقرؤها (`open`, `score`, `el`,
  `pts`, `e`, `st`, `tg`) موجودة، و`active` تتجاهله. **وواجهة V4 مع بيانات V3**: تعمل — حين يغيب `life`
  تعرض الجدول والنصوص القديمة (`v3FramesOld`). مُثبَتٌ في e2e: 32 اختباراً على المثبّتات (صيغة V3) وعلى
  بياناتٍ بصيغة V4.
- **«صفقاتي»** تبقى في متصفّح كلّ مستخدم عند الرجوع إلى V3 (لا تُعرض لأن V3 بلا هذا القسم)، وتعود كما هي
  عند العودة إلى V4. لا شيء منها على الخادم.
- **الصفقات القائمة في V4** لا تُحمَل إلى V3 (V3 بلا دورة حياة)، وحالتها محفوظة في الأرشيف. وعند العودة
  إلى V4 تبدأ الحالة فارغة (لا صفقات بأثرٍ رجعي) — أو تُعاد من الأرشيف يدوياً إن كان الانتقال في نفس اليوم.
- **عاجلٌ للواجهة وحدها** (دون الكود المجدول): `site.yml` يقبل `workflow_dispatch` بمدخل `ref`
  (`gh workflow run site.yml -f ref=v3-stable`). لا يغيّر ما يبنيه المجدول، وأوّلُ دفعٍ إلى main يعيد نشر
  الحالي — فهو للطوارئ لا للرجوع الكامل.
- **بيانات V3 كما نُشرت** (للمقارنة أو للاستعادة اليدوية): `git show data-v3-stable:trades.json`.
